# 文档撰写

## 概述

为代码、API、流程生成清晰、可维护的文档。文档的价值在于 **让读者无需读源码就能正确使用**。

## 文档类型

### 1. README
**结构**:
- 项目名 + 一句话定位
- 快速开始(安装、运行、Hello World)
- 主要功能点
- 配置项
- 常见问题 FAQ
- 贡献指南
- 许可证

### 2. API 文档
**每条 API**:
- 名称 + 简短描述
- 签名(参数类型 + 返回类型)
- 必填 vs 可选参数
- 副作用说明
- 错误码/异常
- 示例(成功 + 失败)

### 3. 函数/方法 JSDoc
```typescript
/**
 * 简述功能
 *
 * @param {Type} name - 参数说明
 * @returns {Type} 返回值说明
 * @throws {ErrorType} 何时抛错
 * @example
 * fn('hello'); // => 'HELLO'
 */
```

### 4. 架构文档
- 系统图(模块 + 关系)
- 数据流(输入 → 处理 → 输出)
- 关键决策(为什么用 X 而不是 Y)
- 已知限制

## 写作原则

### 准确
- 示例必须能跑
- 版本/路径必须真实
- 与代码保持同步(过时文档比没文档更糟)

### 简洁
- 一段话只说一件事
- 避免"可能"等模糊词
- 不复述代码本身

### 可发现
- 标题即问题(如"如何重置密码"而非"密码")
- 善用锚点链接
- 关键信息放在最前面

### 友好
- 默认读者是会用但不会实现的开发者
- 假设合理的先验知识
- 不教条

## 反模式

- ❌ 大段贴代码(应放到代码注释)
- ❌ 含糊描述("做一些处理")
- ❌ 不写错误情况
- ❌ 不更新过时文档
- ❌ 翻译痕迹重的机翻味
- ❌ 文档与代码不同步
