# Bug 修复

## 概述

系统化定位并修复软件缺陷。基于"先复现、再定位、后修复、终验证"四步法,避免在未理解根因的情况下盲目修改。

## 工作流程

### Step 1: 信息收集
- 收集完整的错误堆栈/报错信息
- 询问用户复现步骤(输入、操作序列、环境)
- 确认期望行为 vs 实际行为

### Step 2: 最小复现
- 尝试用最小输入复现问题
- 如果用户提供的是日志/截图,先复现到可运行状态

### Step 3: 根因定位
- 顺着堆栈找到第一处**非框架/库**的代码
- 检查该处的输入参数是否符合预期
- 用 `console.log` / debugger / 单步执行验证假设
- 常见根因清单:
  - 空指针/未定义访问(`undefined.x` / `null.x`)
  - 异步时序问题(race condition / await 缺失)
  - 边界值(空数组/极大数/负数/中文/emoji)
  - 闭包捕获了过期值
  - 类型转换(Number('abc') = NaN)
  - 浮点精度(0.1 + 0.2 !== 0.3)

### Step 4: 修复
- **最小修改原则**:只改必要代码,不做无关重构
- 在根因处修复,不要在症状处打补丁
- 添加注释说明根因(便于后人理解)

### Step 5: 验证
- 重新运行原报错场景
- 跑相关测试用例
- 检查是否有回归

## 输出格式

```
## 根因
[简述根本原因]

## 修复
[说明修改的代码 + 理由]

## 验证
[说明如何验证已修复]
```

## 反模式

- ❌ 看到报错就 try-catch 包住(隐藏问题)
- ❌ 盲目修改直到"看起来对了"
- ❌ 重构无关代码
- ❌ 跳过复现直接改
